# MCPCloud v0.1.4

发布日期：2026-10-29。

修复 v0.1.3 中仍存在的 provider 分页、作用域及费用游标问题，并避免单个 HTTP 客户端断开影响共享就绪探测。

## 修复

- 华为 CES 指标发现以返回的 marker 判断是否继续翻页。Total 表示全部结果，Count 表示当前页；最后一页不再因两者不同而误报 `invalid_provider_response`。
- GCP 仅配置 folder 或 organization 的 profile 可以读取所属项目的固定详情。读取前通过 Resource Manager 核实项目祖先，结果携带验证后的 `folder_ids` / `organization_id`；不属于配置范围的项目在详情调用前被拒绝。
- AWS IAM 的 DSL 查询及原生产品列表将 `service:iam` 下推给 Resource Explorer，避免扫描无关资源耗尽预算。
- 阿里云每日账单和腾讯云默认费用分页允许 Total 在翻页期间增减，继续保持固定上游页大小及页内偏移；已消失的页内尾部按耗尽处理。
- GCP BigQuery 费用游标绑定 profile、项目作用域、账单表、查询作业项目与位置、请求时间范围。跨查询或未绑定的旧格式游标在调用 BigQuery 前返回 `invalid_cursor`；同一查询允许调整结果页大小。
- `/readyz` 共享探测使用独立超时，不继承发起请求的取消信号，避免客户端断开导致失败结果被缓存一分钟。报告及错误的一分钟缓存规则保持不变。

## 升级说明与限制

- GCP 层级作用域详情新增 `resourcemanager.projects.get` 权限要求，用于固定的 `projects.getAncestry` 只读请求；每次详情读取增加一次归属检查。查询失败时不放宽作用域。明确配置项目的 profile 沿用现有检查。费用和监控仍要求项目级 scope。
- 升级后重新开始未完成的查询。游标不跨进程持久化，也不能将旧格式 BigQuery 游标作为新查询的续页。
- 动态账单分页不是一致性快照；上游行的插入、删除或重排仍可能影响多次请求之间的结果。核账应在账单稳定后重新查询。腾讯云国际合作伙伴账单源的规则不变。

## 文档与验证

同步更新 README、安装与配置说明、权限清单、DSL / 工具 / provider 文档、发布命令、平台说明和 changelog。

回归测试覆盖以上六类问题，并在旧实现上复现失败。修复后的全量测试、构建及 provider、probe、engine、HTTP 服务的竞态检查已在 OrbStack Linux 通过。

继续提供 Windows amd64 / arm64 和 Linux amd64 / arm64 四种程序包。发布工作流在对应架构的 GitHub 虚拟机上检查实际解压包的版本、源码提交、MCP 握手及 HTTP 安全边界；验证记录与校验清单随 Release 提供。这些检查不调用真实云账号，不代表七云接口已重新完成现场联调。
