# MCPCloud v0.2.0

发布日期：2026-10-29。

新增从初始化、诊断到 Agent 配置和 Codex 接入的完整命令行流程。用户可以复用已有云身份，选择明确的查询范围，并由 Agent 完成配置预览、保存和客户端注册。

## 新增功能

- `init`：两步向导，先引用已有身份，再选择账号/项目/订阅、区域和资源领域。可选只读范围发现；预览确认后新增 profile，保留原有配置与注释，不覆盖同名 profile。
- `doctor`：文本或 JSON 诊断，区分本地条件、实际库存读取、范围证据及尚未验证的指标/费用/详情权限。支持 `--offline`；配置已保存但诊断失败时，明确保留保存事实。
- `configure`：面向 Agent 的非交互 JSON 接口。默认离线预览不写文件；`--discover` 仅返回范围候选；`--apply --plan-id ID` 检查请求、目标文件和原配置是否与预览一致，然后复用现有保存和 doctor 逻辑。
- `client-config`：生成通用 `mcpServers` JSON 或 Codex 原生 TOML，复用配置校验及绝对路径处理。`--client codex --install` 自动合并 Codex 设置，保留其他 MCP、注释及已有策略，同名匹配可重复执行，冲突不覆盖。
- Codex 配置支持显式目标路径与额外 `--env-var NAME` 引用。只写环境变量名，不读取或复制凭证值；安装报告区分本地注册与实际连接验证。

## 使用示例

```sh
./mcpcloud init --config ./config.yaml
./mcpcloud doctor --config ./config.yaml --json
./mcpcloud client-config --client codex --config ./config.yaml
./mcpcloud client-config --client codex --config ./config.yaml --install
```

Agent 使用独立 JSON 请求先预览，再根据实际授权保存：

```sh
./mcpcloud configure --input request.json --config ./config.yaml
./mcpcloud configure --input request.json --config ./config.yaml --apply --plan-id PLAN_ID_FROM_PREVIEW
```

Windows 将 `./mcpcloud` 换为 `.\mcpcloud.exe`。完整流程见 [初始化指南](https://github.com/SamuelSupe/mcpcloud/blob/v0.2.0/docs/setup.zh-CN.md)、[Agent 操作说明](https://github.com/SamuelSupe/mcpcloud/blob/v0.2.0/docs/agent-setup.md)和 [配置说明](https://github.com/SamuelSupe/mcpcloud/blob/v0.2.0/docs/configuration.md)。程序包内含无密钥 JSON 请求示例 `examples/profile.request.json`，使用前填写自己的范围。

## 升级说明与边界

- 现有 YAML、查询接口和六个只读 MCP 工具保持兼容。新配置功能通过本机 CLI 提供，不新增 MCP 写工具，也不创建云端 IAM 权限或自动登录。
- 配置只引用已有身份。只读发现结果是候选，不自动选择全部账号；GCP/Azure 发现最多一页，华为项目 ID 手动提供。
- `plan.id` 是一致性校验，不是用户授权票据。`saved: true` 与 doctor 通过是独立状态；诊断失败后不要重复保存同名 profile。
- Codex 默认写入 `$CODEX_HOME/config.toml` 或 `~/.codex/config.toml`。项目/profile 配置可用 `--codex-config PATH` 指定；不会自动改变项目信任、工具审批或启用状态。无法安全追加的内联父表、无效 TOML、符号链接和同名冲突会报错并保留原文件。
- 保存配置或安装 Codex 设置不会热重载运行中的服务。重启/重连后核对 `cloud_profiles`，再执行实际查询；Codex 启动环境仍需提供引用的身份。
- doctor 的有界库存探测不代表所有详情、指标和费用权限都已验证。发布验证不访问真实云账号，不扩大此前云端联调结论。
